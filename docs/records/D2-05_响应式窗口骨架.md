## 1. 任务目标

按照 `D2_播放器窗口与视频视口.md` 的 D2-05 定义，建立宽 / 标准 / 窄三类窗口响应式规则，并至少验证：

- `720px`
- `960px`
- `1280px`
- `1600px`

本任务只负责 `window width → layout mode → host constraints`，不提前实现 D3 OSC 内容、D4 Inspector 内容或 D5 状态反馈内容。

核心约束：

- 窄窗口优先降低信息密度，不通过缩小点击目标解决拥挤；
- Inspector 可 overlay 或 dock，但 Video Viewport 不因 Inspector 开关改变真实尺寸；
- 响应式变化必须由规则和 Variable Mode 驱动，不手工维护四套独立播放器；
- D2-01 ～ D2-04 的 Window / Viewport / Header / Host contract 保持有效。

## 9. 视觉表达修复

### 9.1 Variable Scope 创建失败

第一次建立 `V3 / Responsive Semantic` 时，对 BOOLEAN / STRING Variable 写入 `scopes=[]`，当前 Figma Host 不允许该操作，整次 mutation 被原子回滚，无半成品残留。

修正：

- FLOAT / BOOLEAN / STRING 按各自 API 能力创建；
- 不再对 BOOLEAN / STRING 强写 scope。

### 9.2 Semantic Paint opacity 被重置

第一轮 Responsive Board 截图发现 Overlay / OSC / Inspector Host 变成高饱和实体色。

定位：

- Semantic Color binding 后 Paint opacity 被写回 `100%`；
- Header Pod / Policy Chip / Window Border 同样受影响。

统一恢复：

```text
Overlay Host fill     2.5%
OSC Host fill         3%
Inspector Host fill   4.5%
Host stroke           42%
Header compact fill   42%
Header standard fill  52%
Header stroke         48%
Window border         70%
```

第二轮截图恢复为“空间范围”表达，不再被误认成真实 Feature Surface。

### 9.3 Policy Chip 与 Host Label 重叠

第二轮截图发现 Window 内的 Responsive Policy Chip 与 Overlay Host label 信息重叠。

修正：

- 删除四个 Window 内 Policy Chip；
- 响应式策略只保留在 Board 顶部 Mode Matrix；
- 产品 Window 内只显示 Host 几何和职责。

第三轮截图通过。

### 9.4 审计 getter 不可用

最终只读审计尝试读取 `getExplicitVariableModeForCollection()`，当前 Host 不暴露该 getter，因此该只读脚本失败，无任何 mutation。

最终改用：

- Window `responsive-mode` shared data；
- Responsive Variable 本身的三个 Mode；
- 绑定后的实际尺寸解析；

三项交叉验证 Responsive Mode 生效。
