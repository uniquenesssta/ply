# Qt6 + libmpv 播放器阶段实施任务书

> 版本定位：快速框架实施版  
> 范围：R2–R14  
> 原则：先把正确的模块框架和真实主链跑起来，再集中修复、补边界和做强验证。  
> 不包含：R0、R1；现有 R0/R1 状态不在本包中重新定义。

## 统一执行策略

本任务书不要求每个 Atomic Task 都先写成“工程合同”。普通任务只要明确目标、模块、主链、实现重点和基本验证即可直接开工。

整个项目按四个节奏推进：

1. **骨架优先**：先建立真正会被使用的目录、CMake、接口、对象所有权和最小实现，不创建大批空文件。
2. **主链优先**：优先让真实链路工作，例如 `libmpv → PlaybackSession → Render → ViewModel → QML`，先看到结果。
3. **边做边修**：编译错误、接口不顺、职责耦合、明显竞态、真实运行问题出现后立即在影响边界修复；普通边缘问题可记录到阶段修复清单，不要求每个小任务都阻断后续。
4. **集中硬化**：R12 专门负责压力、故障、性能、泄漏、长时间运行和最终架构审查；R13 再做真正发布门禁。

只有以下问题默认视为“必须先停下来解决”的硬阻断：

- 项目无法 configure/build；
- 主链完全不可运行；
- 明确的状态双重拥有、循环依赖或错误模块边界；
- crash、deadlock、use-after-free、线程越界等高风险生命周期问题；
- 数据损坏、不可逆迁移错误；
- Render/mpv 销毁顺序错误；
- 发布阶段安装包无法在干净机器启动。

普通 UI 细节、非主路径边缘场景、尚未覆盖的手工矩阵不需要阻止每个 Atomic Task 继续，但必须在阶段修复清单或 R12/R13 前关闭。

## 模块化总原则

- 一个模块只拥有一个清晰职责；新能力有独立状态、IO、生命周期、错误或测试边界时再拆文件/目录。
- 不为了“文件多”而拆；也不为了“改得少”把不同职责继续塞进同一个文件。
- QML 不直接调用 libmpv；PlaybackSession 是播放真值；Playlist 只拥有队列；DatabaseWorker 只拥有数据库连接；Renderer 只拥有 Render/OpenGL 资源。
- 所有源码/配置/行为变化继续同步记录根 `README.md`。
- R0-06 已按用户要求跳过，因此依赖合法可分发媒体 fixture 的验证，如果只有本地合法样本，必须写成“本地验证”，不能伪装成完整 fixture 体系已经闭环。

# Stage R7：媒体打开与播放列表

## 1. 本阶段最终要得到什么

让播放器真正支持日常“打开媒体”的各种入口，并建立队列。所有入口统一汇入 `MediaOpenCoordinator`，不产生多套加载逻辑。

## 2. 本阶段怎么快速推进

先把本地文件 → Playlist → 当前项 → PlaybackSession 的链路跑通，然后再加拖放、URL、命令行和自动下一项。Playlist UI 先做到可用，性能和细节再修。

## 3. 目标模块结构

```text
src/media/
├─ domain/
├─ application/
└─ infrastructure/
src/playlist/
├─ domain/
├─ application/
└─ presentation/
src/presentation/qml/features/playlist/
```

## 4. 阶段主链

```text
File / Drop / URL / argv
  ↓
MediaOpenCoordinator
  ↓
Playlist Controller / Domain
  ↓ current entry
PlaybackCommand(load)
  ↓
PlaybackSession
```

## 5. 关键状态/资源归属

- 媒体来源规范化：Media module。
- 队列顺序/current entry：Playlist。
- 当前实际加载媒体：PlaybackSession。
- UI 列表：只读 model。

## 6. Atomic Tasks

### R7-01 本地文件选择

**目的**  
把文件选择接入统一 MediaOpenCoordinator。

**主要模块 / 文件**  
`media_open_coordinator.*`、`local_media_validator.*`

**主要链路**  
`file dialog → validate → MediaSource → coordinator → load`

**实施重点**
先支持单文件和取消；权限/失效路径随后补。

**基本验证**
正常/取消/失效路径。

**完成判断**  
本地文件通过统一入口打开。

### R7-02 拖放

**目的**  
支持单/多文件拖放并保持确定顺序。

**主要模块 / 文件**  
`media_drop_handler.*`、DropOverlay

**主要链路**  
`drop payload → classify → ordered MediaOpenRequest`

**实施重点**
先文件/URL；目录可以先明确拒绝。

**基本验证**
单文件、多文件、非媒体。

**完成判断**  
拖放不直接调 mpv。

### R7-03 URL 打开

**目的**  
支持基础 HTTP/HTTPS 媒体 URL。

**主要模块 / 文件**  
`url_media_validator.*`、`url_open_workflow.*`

**主要链路**  
`input URL → validate → MediaSource → coordinator`

**实施重点**
只做 URL 结构/scheme，不做网站解析。

**基本验证**
正常 URL、空值、不可达。

**完成判断**  
网络媒体进入同一播放链。

### R7-04 命令行和文件关联入口

**目的**  
把外部参数统一送入 MediaOpenCoordinator。

**主要模块 / 文件**  
argument parser + coordinator

**主要链路**  
`argv/external request → MediaOpenRequest → coordinator`

**实施重点**
先支持当前进程 argv；R10 单实例再接第二实例。

**基本验证**
单个/多个路径。

**完成判断**  
入口不会分叉成多套 load。

### R7-05 Playlist Domain

**目的**  
建立 Playlist/Entry/current/repeat/shuffle 的纯模型。

**主要模块 / 文件**  
`src/playlist/domain/`

**主要链路**  
`playlist commands → authoritative queue`

**实施重点**
稳定 entry ID；先增删/选择，再补 repeat/shuffle。

**基本验证**
增删/当前项/空列表。

**完成判断**  
队列有单一 owner。

### R7-06 Playlist Controller

**目的**  
连接 Playlist、MediaOpenCoordinator、readonly model。

**主要模块 / 文件**  
`playlist_controller.*`、`playlist_mutation.*`

**主要链路**  
`UI intent → controller → domain → model/load workflow`

**实施重点**
model 只读；失败时不留悬空 current。

**基本验证**
添加/删除/重排/选择。

**完成判断**  
所有修改经过 controller。

### R7-07 Playlist QML

**目的**  
做可用的播放列表抽屉。

**主要模块 / 文件**  
`qml/features/playlist/`

**主要链路**  
`readonly model → list/delegate → controller actions`

**实施重点**
current/selected/hover 分开；先可用，再优化大列表。

**基本验证**
空列表、长标题、几十/几百项。

**完成判断**  
列表可增删选择。

### R7-08 自动下一项

**目的**  
EOF 后按 repeat/shuffle 推进。

**主要模块 / 文件**  
`playlist_auto_advance.*`、`navigation.*`

**主要链路**  
`Playback ended → policy → next entry → load`

**实施重点**
区分用户 stop 和自然 EOF；先 normal/repeat all，再补 shuffle。

**基本验证**
EOF、列表尾、repeat one/all。

**完成判断**  
不会双 load。

### R7-09 删除当前项

**目的**  
明确删除正在播放项后的行为。

**主要模块 / 文件**  
playlist mutation/navigation

**主要链路**  
`remove current → next/stop policy → coordinated state`

**实施重点**
先选一个简单一致策略并记录；后续 UX 可调整。

**基本验证**
只有1项/最后一项/播放中。

**完成判断**  
无 dangling current ID。

## 7. 框架打通后优先修复

- 多入口行为不一致。
- 删除 current 后悬空 ID。
- 自动下一项与用户 stop 混淆。
- 多文件拖放顺序。
- 大列表 delegate 性能。

## 8. 本阶段最小可运行里程碑

能通过文件选择、拖放、URL 打开媒体；列表能添加、删除、选择并在 EOF 后继续下一项。

## 9. 阶段关闭条件

所有入口都走 MediaOpenCoordinator；Playlist 有唯一 owner；主队列操作稳定。极端大列表和复杂 shuffle 可以继续修，不阻断 R8。

## 10. 本阶段暂不要求

媒体库、目录扫描、在线站点解析不在 R7。

## 11. 后续扩展位置

未来媒体库归 `library`，站点解析归 `sources/resolvers`，都只能输出 MediaOpenRequest。
