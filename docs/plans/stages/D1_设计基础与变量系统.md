# Qt6 + libmpv 播放器第三版 UI 阶段设计任务书

> 版本定位：第三版 Airy Glass 独立 UI/UX 设计任务书  
> 设计基准：已确认的浅雾、柔紫蓝、柔焦、半透明玻璃、强留白、轻悬浮视觉方向  
> 设计对象：Qt6 + libmpv 桌面播放器  
> 文档性质：设计执行基线，不替代源码开发 R2–R14 任务书  
> 组织原则：按窗口、控制系统、Inspector、状态、Preferences、设计系统、原型与交付组织，不把播放器功能误写成网页“页面”  
> 设计阶段编号：D0–D9

## 统一执行策略

本任务书学习现有 `docs/plans` 与 `docs/plans/stages` 的写法：阶段目标明确、职责边界明确、Atomic Task 可独立验收、先搭正确骨架再逐步收口；但**内容完全独立于旧 R2–R14 开发任务书**。

整个第三版 UI 设计按以下节奏推进：

1. **视觉母语优先**：先锁定已经确认的 Airy Glass 基准，不再在执行中回到深色黑蓝播放器、传统后台面板或旧 IINA 复刻。
2. **产品结构优先**：先明确 Player Window、Video Viewport、Floating Header、OSC、Inspector、Overlay、Preferences、Mini/Fullscreen 的空间关系，再设计局部控件。
3. **真实场景优先**：所有组件都必须来自真实播放器场景；不为了“组件库看起来完整”提前创建没有产品落点的组件。
4. **源组件优先**：一旦发现跨场景重复的视觉或交互，必须回到 Token / Primitive / Component / Surface 源处理，不在多个成品画面分别打补丁。
5. **全局回刷**：圆角、玻璃材质、间距、图标、时间轴、按钮尺寸、显隐逻辑发生基准变化时，必须全局同步，不允许只改一个窗口模式。
6. **最后文档化**：Handoff、变量统计、组件清单、交互说明必须从最终设计反推，不允许先写过期规格再强迫产品稿适配。

### 默认硬阻断

出现以下任一情况时，不得继续铺开后续设计：

- 主播放器框架仍与前两版视觉骨架高度相似；
- 同一控件在主窗口、Fullscreen、Mini 中出现三套独立实现；
- Playlist / Tracks / Subtitles / Chapters 形成四套不同的侧板语言；
- 窗口、OSC、Inspector、Preferences 之间明显不像同一个产品；
- 关键控件存在肉眼可见的未对齐、非光学居中、行高漂移、间距不一致；
- Figma 组件源和成品实例出现无法解释的硬编码颜色、圆角、阴影、尺寸分叉；
- 状态展示依赖“大色块、大圆按钮、大红框”掩盖层级问题；
- 为了追求玻璃效果牺牲可读性、焦点可见性或复杂视频背景下的辨识度。

## 模块化总原则

- Figma 的 Page 只是设计文件分类容器，不代表产品“页面”。
- 产品结构必须按 **Window / Region / Overlay / Inspector / State / Component** 理解。
- 主播放器窗口只拥有布局组合，不拥有各 Feature 的内部组件实现。
- OSC 只负责播放器控制系统，不承载 Playlist/Tracks/Settings 的业务内容。
- Inspector Shell 只负责容器、标题区、尺寸、材质、开合和切换；Playlist/Tracks/Subtitles/Chapters 各自只负责内容模块。
- HUD / Toast / Dialog / Error Overlay 是不同反馈层级，禁止混成一个万能浮层。
- Mini Player / Fullscreen 是同一播放器的不同窗口模式，不复制第二套播放状态。
- Token 是视觉真值；Component 是交互/几何真值；成品画面只消费它们。
- 任何一个 Figma Component 一旦需要承担第二项可独立演进职责，应升级为 Component Set 或拆成子组件，不继续在单组件内部堆 Variant 例外。

# Stage D1：设计基础与变量系统

## 1. 本阶段最终要得到什么

建立第三版真正服务产品的基础 Token：颜色、文字、间距、圆角、玻璃、Blur、阴影、透明度、Motion、Z-order。D1 不是制作“漂亮变量墙”，而是为 D2–D7 提供统一视觉真值。

## 2. 本阶段怎么快速推进

先从三张已确认框架抽取真实值，再补状态和响应式所需 Token。不要先凭想象创建数百个变量。Primitive 与 Semantic 分开，成品只使用 Semantic。

## 3. 目标变量结构

```text
Variables
├─ primitive/
│  ├─ color/
│  ├─ alpha/
│  ├─ radius/
│  ├─ spacing/
│  ├─ size/
│  ├─ blur/
│  ├─ shadow/
│  └─ duration/
└─ semantic/
   ├─ surface/
   ├─ text/
   ├─ border/
   ├─ accent/
   ├─ feedback/
   ├─ control/
   ├─ inspector/
   └─ motion/
```

## 4. 阶段主链

```text
Confirmed Framework
  ↓ sample
Primitive Tokens
  ↓ alias
Semantic Tokens
  ↓
Components / Surfaces / Product Screens
```

## 5. 关键状态 / 资源归属

- RGB/alpha 原始值：Primitive。
- “玻璃背景/主要文字/选中态”等产品语义：Semantic。
- 成品实例：只绑定 Semantic。
- Hover/Pressed/Focus 的值：Control semantic state。
- 复杂视频背景：必须通过专门的 scrim/contrast token 解决，不在单页面私调。

## 6. Atomic Tasks
### D1-01 建立浅雾基础色谱

**目的**  
从确认框架提取雾白、冷灰白、柔紫、蓝紫、天青、暖奶油光、深文字色和状态色。

**主要模块 / 设计对象**  
Variables / primitive/color

**主要链路**  
`framework palette → primitive color`

**实施重点**  
避免建立传统 brand blue 体系；强调色数量少，亮度层级清楚。

**基本验证**  
在浅背景、视频背景、玻璃背景分别检查。

**完成判断**  
主视觉无需纯黑和大面积高饱和蓝也能成立。
### D1-02 建立语义颜色

**目的**  
将 primitive 映射到 surface/text/border/accent/selection/focus/feedback。

**主要模块 / 设计对象**  
Variables / semantic/color

**主要链路**  
`primitive → semantic → component`

**实施重点**  
selected、focus、hover 必须是不同语义；错误状态不允许直接使用纯红实体框。

**基本验证**  
随机抽 10 个成品元素追溯变量链。

**完成判断**  
成品不依赖原始色值。
### D1-03 建立 Typography System

**目的**  
定义 Display/Title/Body/Label/Caption/Timecode/Keycap 等层级。

**主要模块 / 设计对象**  
Text styles + typography variables

**主要链路**  
`type scale → semantic styles → product`

**实施重点**  
大标题允许较强 Grotesk 气质；播放器内控件文字必须更克制；timecode 需要数字稳定性。

**基本验证**  
长媒体标题、中英混排、00:00:00 时间码。

**完成判断**  
文字层级不靠随意字号差异维持。
### D1-04 建立 Spacing / Size / Radius

**目的**  
把强留白和小控件密度写成数值体系。

**主要模块 / 设计对象**  
spacing/size/radius variables

**主要链路**  
`primitive metrics → semantic layout`

**实施重点**  
区分页面/窗口级留白、Panel 内边距、Control gap、List row gap；圆角按 Surface/Control/Pill 分层。

**基本验证**  
对 Main/Inspector/Preferences 做间距标注检查。

**完成判断**  
同类结构不出现 13/15/17 这类无语义随机值。
### D1-05 建立 Glass / Blur / Shadow

**目的**  
定义浮动玻璃、强玻璃、Inspector、HUD、Dialog 等材质层级。

**主要模块 / 设计对象**  
blur/opacity/shadow semantic tokens

**主要链路**  
`video/background → glass material → content`

**实施重点**  
优先半透明亮色玻璃与柔和 Blur；阴影只做空间分离，不制造黑卡片。

**基本验证**  
在明亮花田、暗部、暖色高光三种背景上检查可读性。

**完成判断**  
玻璃材质在复杂背景下仍稳定可读。
### D1-06 建立 Motion / Opacity / Z-order

**目的**  
定义 OSC 显隐、Popover、Inspector、HUD、Dialog 的动效与层级。

**主要模块 / 设计对象**  
duration/opacity/z semantic tokens

**主要链路**  
`interaction state → motion token → component`

**实施重点**  
默认动效轻、短、无弹跳炫技；支持 reduce motion；Overlay 层级不能互相争抢。

**基本验证**  
OSC/Inspector/Dialog 同时出现的 prototype smoke。

**完成判断**  
没有两套 timer/transition 规则。

## 7. 框架打通后优先修复

- 成品残留硬编码色值、圆角、Blur、Shadow。
- 强调色使用面积过大。
- 玻璃在浅色视频区域失去边界。
- 文本灰度太淡导致可读性下降。
- 同一类控件因窗口模式不同偷偷改 token。

## 8. 本阶段最小可评审里程碑

三张核心框架完全由 Token 驱动；修改一个 Surface/Accent/Spacing 语义变量能可预测地影响对应实例。

## 9. 阶段关闭条件

D2–D7 所需基础 Token 齐全；成品关键区域无无解释硬编码；复杂背景可读性通过。

## 10. 本阶段暂不要求

不为未来插件、媒体库、在线字幕等未确定功能建立 Token。

## 11. 后续扩展位置

真实产品出现新的独立视觉语义时再补 Semantic；只有两个以上语义共同复用时才新增 Primitive。
