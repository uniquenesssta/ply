# Qt6 + libmpv 播放器阶段实施任务书

> 版本定位：快速框架实施版  
> 范围：R2–R14  
> 原则：先把正确的模块框架和真实主链跑起来，再集中修复、补边界和做强验证。  
> 不包含：R0、R1；现有 R0/R1 状态不在本包中重新定义。

## 统一执行策略

本任务书不要求每个 Atomic Task 都先写成“工程合同”。普通任务只要明确目标、模块、主链、实现重点和基本验证即可直接开工。

整个项目按四个节奏推进：

1. **骨架优先**：先建立真正会被使用的目录、CMake、接口、对象所有权和最小实现，不创建大批空文件。
2. **主链优先**：优先让真实链路工作，例如 `libmpv → PlaybackSession → Render → ViewModel → QML`，先看到结果。
3. **边做边修**：编译错误、接口不顺、职责耦合、明显竞态、真实运行问题出现后立即在影响边界修复；普通边缘问题可记录到阶段修复清单，不要求每个小任务都阻断后续。
4. **集中硬化**：R12 专门负责压力、故障、性能、泄漏、长时间运行和最终架构审查；R13 再做真正发布门禁。

只有以下问题默认视为“必须先停下来解决”的硬阻断：

- 项目无法 configure/build；
- 主链完全不可运行；
- 明确的状态双重拥有、循环依赖或错误模块边界；
- crash、deadlock、use-after-free、线程越界等高风险生命周期问题；
- 数据损坏、不可逆迁移错误；
- Render/mpv 销毁顺序错误；
- 发布阶段安装包无法在干净机器启动。

普通 UI 细节、非主路径边缘场景、尚未覆盖的手工矩阵不需要阻止每个 Atomic Task 继续，但必须在阶段修复清单或 R12/R13 前关闭。

## 模块化总原则

- 一个模块只拥有一个清晰职责；新能力有独立状态、IO、生命周期、错误或测试边界时再拆文件/目录。
- 不为了“文件多”而拆；也不为了“改得少”把不同职责继续塞进同一个文件。
- QML 不直接调用 libmpv；PlaybackSession 是播放真值；Playlist 只拥有队列；DatabaseWorker 只拥有数据库连接；Renderer 只拥有 Render/OpenGL 资源。
- 所有源码/配置/行为变化继续同步记录根 `README.md`。
- R0-06 已按用户要求跳过，因此依赖合法可分发媒体 fixture 的验证，如果只有本地合法样本，必须写成“本地验证”，不能伪装成完整 fixture 体系已经闭环。

# Stage R8：音轨、字幕、章节

## 1. 本阶段最终要得到什么

补齐主流播放器最常用的媒体内部结构：音轨、字幕、外挂字幕、延迟和章节。R8 完成后功能形态已经接近成熟播放器核心。

## 2. 本阶段怎么快速推进

先把 `track-list → decoder → Snapshot → model → selection` 一条链跑通，再加外挂字幕和 delay；章节最后单独接 Seek。不要一开始就为所有 mpv track 字段建立复杂模型。

## 3. 目标模块结构

```text
src/tracks/
├─ domain/
├─ application/
└─ presentation/
src/chapters/（若按实际结构独立）
src/presentation/qml/features/tracks/
src/presentation/qml/features/chapters/
```

## 4. 阶段主链

```text
mpv track/chapter properties
  ↓
Decoder
  ↓
PlaybackSnapshot
  ↓
Read-only Models / ViewModels
  ↓
QML selection
  ↓
PlaybackCommand
```

## 5. 关键状态/资源归属

- Track/Chapter 真值：PlaybackSnapshot。
- QML model：投影。
- track ID：后端稳定 ID，不是 ListView index。

## 6. Atomic Tasks

### R8-01 Track decoder

**目的**  
把 mpv track-list 变成产品 TrackDescriptor。

**主要模块 / 文件**  
tracks domain + mpv track decoder

**主要链路**  
`mpv node → decoder → track descriptors → snapshot`

**实施重点**
先音频/字幕必要字段；缺字段用 optional。

**基本验证**
多音轨/多字幕真实媒体。

**完成判断**  
上层不解析 mpv node。

### R8-02 Track list models

**目的**  
把 tracks 变成 QML 只读模型。

**主要模块 / 文件**  
audio/subtitle list model

**主要链路**  
`Snapshot tracks → model replace → QML`

**实施重点**
媒体切换直接整表替换。

**基本验证**
A→B 媒体切换。

**完成判断**  
旧轨道不残留。

### R8-03 轨道选择

**目的**  
支持音轨和字幕选择/字幕关闭。

**主要模块 / 文件**  
`track_selection.*` + QML

**主要链路**  
`track id → command → backend → snapshot`

**实施重点**
最终 selected 以 backend/snapshot 为准。

**基本验证**
选择成功/失败/off。

**完成判断**  
UI 与实际轨道一致。

### R8-04 外挂字幕

**目的**  
支持添加 SRT/ASS。

**主要模块 / 文件**  
external_subtitle_loader.*

**主要链路**  
`file → validate → subtitle load → track refresh`

**实施重点**
先本地文件；重复/编码错误后补。

**基本验证**
SRT/ASS/错误路径。

**完成判断**  
外挂字幕进入同一模型。

### R8-05 字幕延迟

**目的**  
支持正负字幕 delay 和 reset。

**主要模块 / 文件**  
subtitle_delay_controller.*

**主要链路**  
`input → command → snapshot → HUD`

**实施重点**
先固定合理 step/范围。

**基本验证**
正/负/reset。

**完成判断**  
显示和实际效果一致。

### R8-06 音频延迟

**目的**  
独立实现 audio delay。

**主要模块 / 文件**  
audio_delay_controller.*

**主要链路**  
`input → command → snapshot`

**实施重点**
与 subtitle delay 分开状态。

**基本验证**
正/负/reset。

**完成判断**  
互不影响。

### R8-07 Chapter decoder/model

**目的**  
建立章节模型。

**主要模块 / 文件**  
chapter decoder/model

**主要链路**  
`mpv chapter-list → descriptors → readonly model`

**实施重点**
无标题用 fallback；媒体切换清空。

**基本验证**
无章节/多章节。

**完成判断**  
章节列表稳定。

### R8-08 Chapter UI

**目的**  
章节点击直接走 Seek 命令。

**主要模块 / 文件**  
chapter feature QML/VM

**主要链路**  
`chapter click → Seek command → snapshot → timeline`

**实施重点**
不直接写 timeline thumb。

**基本验证**
点击章节、non-seekable。

**完成判断**  
章节跳转和 Timeline 同步。

## 7. 框架打通后优先修复

- 媒体切换旧列表残留。
- selection 失败后 UI 假选中。
- 外挂字幕重复/错误。
- chapter 点击与 Timeline 双写。

## 8. 本阶段最小可运行里程碑

多音轨/多字幕媒体可以切换；外挂 SRT/ASS 可加载；字幕/音频 delay 可调；章节可以点击跳转。

## 9. 阶段关闭条件

核心轨道/字幕/章节主链稳定；媒体切换能整体替换旧状态。复杂语言排序、极端编码等可以继续修。

## 10. 本阶段暂不要求

在线字幕搜索、字幕下载和高级字幕编辑不在 R8。

## 11. 后续扩展位置

在线字幕以后独立 `subtitles/search`；高级字幕样式在 R11。
