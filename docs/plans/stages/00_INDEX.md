# R2–R14 快速框架实施版索引

## 这版与上一预览版的区别

- 阶段级内容继续详细：目标、结构、主链、状态归属、阶段里程碑、修复清单、完成条件都保留。
- 普通 Atomic Task 大幅简化，只保留：目的、模块、主链、实施重点、基本验证、完成判断。
- 只有高风险任务额外增加“高风险约束”。
- 明确采用“骨架优先、主链优先、边跑边修、R12 集中硬化”的开发节奏。
- 不要求每个小任务覆盖全部边缘场景后才能继续。
- 仍然保持职责模块化，不能以“快速”为理由把所有东西堆回单文件。
- 自 2026-08-07 起，新增《成熟播放器行为补强与验收矩阵》，吸收 Screenbox 中有价值的成熟播放器行为边界；它只增加行为完整性、竞态和验收要求，不改变本项目 Qt6 + libmpv 架构或 MVP 范围。

## 执行基线组成

R2–R14 后续开发必须同时读取：

1. 根目录 `ALL_AI_CODE.md`；
2. 根目录 `AI_PROJECT_RULES.md`；
3. 原始完整任务书 `../Qt6-libmpv播放器-完整模块化开发任务书.md`；
4. 当前 Stage 对应任务书；
5. [成熟播放器行为补强与验收矩阵.md](成熟播放器行为补强与验收矩阵.md)。

《成熟播放器行为补强与验收矩阵》从 **R2-02** 起生效，不追溯重写 R2-01 已实现内容。它定义的新增 Atomic Task 可以在原任务实现时一并完成，但必须有实际代码/测试/验证事实，不能用空提交机械关闭。

若补强矩阵与原有架构边界发生冲突，以原始完整任务书的分层、状态所有权、libmpv 隔离和当前用户明确要求为准；补强矩阵只允许增加成熟播放器行为、边界场景、竞态处理和验收覆盖，不允许借参考项目改变技术路线或扩大产品范围。

## 推荐执行方式

当前已经进入 R2。R2-01 继续按既定计划完成 MSYS2/CLANG64 源码构建和固定 libmpv sibling package 本机验收，不因本次任务书更新返工。

从 R2-02 起，直接以“当前阶段任务书 + 成熟播放器行为补强矩阵”为联合执行基线。每个 Atomic Task 开始时仍要结合当时真实代码做影响分析，而不是机械照任务书创建所有规划文件。

若某个普通任务主链已经工作但还有非阻断边缘问题，可记录在该阶段“框架打通后优先修复”中继续推进；涉及 crash、deadlock、UAF、数据损坏、错误状态所有权、旧 generation 污染当前媒体、重复 auto-advance、Render/mpv 销毁顺序错误或无法 build 的问题必须立即处理。
