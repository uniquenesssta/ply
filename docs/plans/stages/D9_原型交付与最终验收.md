# Qt6 + libmpv 播放器第三版 UI 阶段设计任务书

> 版本定位：第三版 Airy Glass 独立 UI/UX 设计任务书  
> 设计基准：已确认的浅雾、柔紫蓝、柔焦、半透明玻璃、强留白、轻悬浮视觉方向  
> 设计对象：Qt6 + libmpv 桌面播放器  
> 文档性质：设计执行基线，不替代源码开发 R2–R14 任务书  
> 组织原则：按窗口、控制系统、Inspector、状态、Preferences、设计系统、原型与交付组织，不把播放器功能误写成网页“页面”  
> 设计阶段编号：D0–D9

## 统一执行策略

本任务书学习现有 `docs/plans` 与 `docs/plans/stages` 的写法：阶段目标明确、职责边界明确、Atomic Task 可独立验收、先搭正确骨架再逐步收口；但**内容完全独立于旧 R2–R14 开发任务书**。

整个第三版 UI 设计按以下节奏推进：

1. **视觉母语优先**：先锁定已经确认的 Airy Glass 基准，不再在执行中回到深色黑蓝播放器、传统后台面板或旧 IINA 复刻。
2. **产品结构优先**：先明确 Player Window、Video Viewport、Floating Header、OSC、Inspector、Overlay、Preferences、Mini/Fullscreen 的空间关系，再设计局部控件。
3. **真实场景优先**：所有组件都必须来自真实播放器场景；不为了“组件库看起来完整”提前创建没有产品落点的组件。
4. **源组件优先**：一旦发现跨场景重复的视觉或交互，必须回到 Token / Primitive / Component / Surface 源处理，不在多个成品画面分别打补丁。
5. **全局回刷**：圆角、玻璃材质、间距、图标、时间轴、按钮尺寸、显隐逻辑发生基准变化时，必须全局同步，不允许只改一个窗口模式。
6. **最后文档化**：Handoff、变量统计、组件清单、交互说明必须从最终设计反推，不允许先写过期规格再强迫产品稿适配。

### 默认硬阻断

出现以下任一情况时，不得继续铺开后续设计：

- 主播放器框架仍与前两版视觉骨架高度相似；
- 同一控件在主窗口、Fullscreen、Mini 中出现三套独立实现；
- Playlist / Tracks / Subtitles / Chapters 形成四套不同的侧板语言；
- 窗口、OSC、Inspector、Preferences 之间明显不像同一个产品；
- 关键控件存在肉眼可见的未对齐、非光学居中、行高漂移、间距不一致；
- Figma 组件源和成品实例出现无法解释的硬编码颜色、圆角、阴影、尺寸分叉；
- 状态展示依赖“大色块、大圆按钮、大红框”掩盖层级问题；
- 为了追求玻璃效果牺牲可读性、焦点可见性或复杂视频背景下的辨识度。

## 模块化总原则

- Figma 的 Page 只是设计文件分类容器，不代表产品“页面”。
- 产品结构必须按 **Window / Region / Overlay / Inspector / State / Component** 理解。
- 主播放器窗口只拥有布局组合，不拥有各 Feature 的内部组件实现。
- OSC 只负责播放器控制系统，不承载 Playlist/Tracks/Settings 的业务内容。
- Inspector Shell 只负责容器、标题区、尺寸、材质、开合和切换；Playlist/Tracks/Subtitles/Chapters 各自只负责内容模块。
- HUD / Toast / Dialog / Error Overlay 是不同反馈层级，禁止混成一个万能浮层。
- Mini Player / Fullscreen 是同一播放器的不同窗口模式，不复制第二套播放状态。
- Token 是视觉真值；Component 是交互/几何真值；成品画面只消费它们。
- 任何一个 Figma Component 一旦需要承担第二项可独立演进职责，应升级为 Component Set 或拆成子组件，不继续在单组件内部堆 Variant 例外。

# Stage D9：原型、交付与最终验收

## 1. 本阶段最终要得到什么

把第三版从“高保真设计稿”变成可执行的设计交付：真实原型链、状态说明、尺寸契约、Token/Component 说明、响应式规则、复杂背景可读性与开发验收矩阵全部闭环。

## 2. 本阶段怎么快速推进

先建最关键的真实点击链，再写 Handoff。所有 Handoff 数字从最终 Token/组件实例读取，不手填旧值。最后做全局截图与结构审计。

## 3. 目标交付结构

```text
Prototype
├─ Open / Play / Pause
├─ Seek
├─ Inspector switch
├─ Subtitle / Track selection
├─ Fullscreen
├─ Mini transition
└─ Error recovery

Handoff
├─ Product structure
├─ Layout contracts
├─ Tokens
├─ Components
├─ Interaction states
├─ Responsive rules
├─ Accessibility
└─ QA matrix
```

## 4. 阶段主链

```text
Final Design
  ↓
Interactive Prototype
  ↓
Handoff Contracts
  ↓
Global QA
  ↓
Implementation Ready
```

## 5. 关键状态 / 资源归属

- Prototype 只演示交互，不创建第二套视觉。
- Handoff 只记录最终事实。
- 开发映射说明不能把 QML 实现当成已完成。
- 所有尺寸/颜色/动效以最终 Design System 为准。

## 6. Atomic Tasks
### D9-01 核心播放原型

**目的**  
建立 play/pause、OSC 显隐、基础媒体状态跳转。

**主要模块 / 设计对象**  
Prototype / transport

**主要链路**  
`click/move/inactivity → state transitions`

**实施重点**  
使用真实 Component Instance；不画静态流程图冒充原型。

**基本验证**  
点击链逐屏核对。

**完成判断**  
可演示主播放交互。
### D9-02 Timeline Seek 原型

**目的**  
演示 hover preview、scrub、commit、pending。

**主要模块 / 设计对象**  
Prototype / timeline

**主要链路**  
`pointer down → scrub → commit → resume`

**实施重点**  
明确拖动所有权和真实 position 恢复。

**基本验证**  
完整拖动链。

**完成判断**  
开发能理解交互阶段。
### D9-03 Inspector 原型

**目的**  
演示打开、切换 Playlist/Tracks/Subtitles/Chapters、关闭。

**主要模块 / 设计对象**  
Prototype / inspector

**主要链路**  
`action → inspector → mode switch → close`

**实施重点**  
保持同一 Shell；窄窗口覆盖规则可演示。

**基本验证**  
四模式切换。

**完成判断**  
Inspector 不是四个独立页面。
### D9-04 Window Mode 原型

**目的**  
演示 Windowed↔Fullscreen↔Mini。

**主要模块 / 设计对象**  
Prototype / window modes

**主要链路**  
`mode action → transition → shared state`

**实施重点**  
视觉过渡克制；临时 popup 状态合理清理。

**基本验证**  
往返切换。

**完成判断**  
模式转换逻辑清晰。
### D9-05 错误与恢复原型

**目的**  
演示 Error Overlay、详情/关闭/重试或重新打开。

**主要模块 / 设计对象**  
Prototype / feedback

**主要链路**  
`error → action → recovery`

**实施重点**  
不制造过多错误页面；动作层级清楚。

**基本验证**  
可恢复/不可恢复。

**完成判断**  
错误链闭环。
### D9-06 Handoff 规格

**目的**  
整理布局、尺寸、Token、组件、状态、响应式、可访问性契约。

**主要模块 / 设计对象**  
Handoff board

**主要链路**  
`final sources → documented contracts`

**实施重点**  
所有数字来自真实源；标注哪些是视觉目标、哪些是交互契约。

**基本验证**  
与组件源交叉核对。

**完成判断**  
开发不需要从截图猜规则。
### D9-07 全局视觉 QA

**目的**  
对 Main/Inspector/States/Preferences/Fullscreen/Mini 做最终截图审计。

**主要模块 / 设计对象**  
QA matrix

**主要链路**  
`representative screens → alignment/material/spacing checks`

**实施重点**  
重点检查对齐、光学中心、玻璃可读性、间距、信息密度。

**基本验证**  
100% 截图 + 复杂背景。

**完成判断**  
无已知肉眼小错误。
### D9-08 结构与设计系统 QA

**目的**  
检查变量、组件、实例、命名、Prototype reaction。

**主要模块 / 设计对象**  
Design structure audit

**主要链路**  
`file structure → audit → close gaps`

**实施重点**  
空页、Detached、硬编码、断 Alias、默认层名、重复 Component、失效 Reaction 全部检查。

**基本验证**  
逐项 checklist。

**完成判断**  
设计文件结构可长期维护。

## 7. 框架打通后优先修复

D9 本身就是交付收口阶段。任何明确缺口必须回对应 D0–D8 根因修，不在 Handoff 用文字掩盖。

## 8. 本阶段最小可评审里程碑

可以从 Main Player 开始，完整演示播放控制、Seek、Inspector、Fullscreen/Mini 和错误恢复；Handoff 能解释所有公共组件和响应式规则。

## 9. 阶段关闭条件

原型可点击；Handoff 与最终设计一致；全局 QA 无已知结构或视觉阻断；第三版设计可以进入 Qt Quick/QML 实现。

## 10. 本阶段暂不要求

不要求在 Figma 内模拟真实 libmpv 性能、网络延迟或平台 API。

## 11. 后续扩展位置

开发中发现设计契约缺失时，回到对应 D 阶段补规则；不在实现代码中私自发明新的视觉语义。
