# Qt6 + libmpv 播放器阶段实施任务书

> 版本定位：快速框架实施版  
> 范围：R2–R14  
> 原则：先把正确的模块框架和真实主链跑起来，再集中修复、补边界和做强验证。  
> 不包含：R0、R1；现有 R0/R1 状态不在本包中重新定义。

## 统一执行策略

本任务书不要求每个 Atomic Task 都先写成“工程合同”。普通任务只要明确目标、模块、主链、实现重点和基本验证即可直接开工。

整个项目按四个节奏推进：

1. **骨架优先**：先建立真正会被使用的目录、CMake、接口、对象所有权和最小实现，不创建大批空文件。
2. **主链优先**：优先让真实链路工作，例如 `libmpv → PlaybackSession → Render → ViewModel → QML`，先看到结果。
3. **边做边修**：编译错误、接口不顺、职责耦合、明显竞态、真实运行问题出现后立即在影响边界修复；普通边缘问题可记录到阶段修复清单，不要求每个小任务都阻断后续。
4. **集中硬化**：R12 专门负责压力、故障、性能、泄漏、长时间运行和最终架构审查；R13 再做真正发布门禁。

只有以下问题默认视为“必须先停下来解决”的硬阻断：

- 项目无法 configure/build；
- 主链完全不可运行；
- 明确的状态双重拥有、循环依赖或错误模块边界；
- crash、deadlock、use-after-free、线程越界等高风险生命周期问题；
- 数据损坏、不可逆迁移错误；
- Render/mpv 销毁顺序错误；
- 发布阶段安装包无法在干净机器启动。

普通 UI 细节、非主路径边缘场景、尚未覆盖的手工矩阵不需要阻止每个 Atomic Task 继续，但必须在阶段修复清单或 R12/R13 前关闭。

## 软件可用性里程碑

| 里程碑 | 达到的实际形态 |
|---|---|
| R2 | 无 UI 的 libmpv 播放核心可真实加载/播放/Seek/关闭 |
| R3 | 播放状态、线程、命令/事件稳定，形成真正“播放器内核” |
| R4 | 视频真正进入 Qt Quick，开始像一个播放器 |
| R6 | 主窗口、播放/暂停、Timeline、音量、全屏可用，形成基础桌面播放器 |
| R8 | 文件/URL/播放列表/音轨/字幕/章节完整，达到主流播放器核心功能形态 |
| R10 | 历史/设置/快捷键/媒体键/单实例/文件关联齐全，Windows 日常使用基本完整 |
| R11 | 高级能力增强 |
| R12 | 稳定性和性能收敛 |
| R13 | 可发给别人安装使用的 Windows 正式桌面软件 |
| R14 | macOS/Linux 平台适配 |

## 模块化总原则

- 一个模块只拥有一个清晰职责；新能力有独立状态、IO、生命周期、错误或测试边界时再拆文件/目录。
- 不为了“文件多”而拆；也不为了“改得少”把不同职责继续塞进同一个文件。
- QML 不直接调用 libmpv；PlaybackSession 是播放真值；Playlist 只拥有队列；DatabaseWorker 只拥有数据库连接；Renderer 只拥有 Render/OpenGL 资源。
- 所有源码/配置/行为变化继续同步记录根 `README.md`。
- R0-06 已按用户要求跳过，因此依赖合法可分发媒体 fixture 的验证，如果只有本地合法样本，必须写成“本地验证”，不能伪装成完整 fixture 体系已经闭环。

# Stage R11：高级播放能力

## 1. 本阶段最终要得到什么

在基础播放器已经可用后，逐项增加高级功能。每项都是独立 Feature，不需要一次把所有高级能力都做完，也不能为了方便塞回 PlayerScreen。

## 2. 本阶段怎么快速推进

每项遵循轻量链：先产品语义 → 应用 workflow → mpv/platform adapter → Feature QML → 挂入口。一个功能主链跑通就可以提交，再逐步修边缘。

## 3. 目标模块结构

```text
src/screenshots/
src/playback/.../advanced feature modules/
src/video_adjustments/
src/shaders/
src/presentation/qml/features/<feature>/
src/platform/.../pip/
```

## 4. 阶段主链

```text
Feature intent
  ↓
Domain model / typed command
  ↓
Workflow
  ↓
mpv / platform adapter
  ↓
Snapshot / Result
  ↓
Feature QML
```

## 5. 关键状态/资源归属

每项各自拥有自己的设置/临时状态；所有最终播放真值仍回到 PlaybackSnapshot 或对应 SettingsController。

## 6. Atomic Tasks

### R11-01 截图

**目的**  
增加截图请求、目录/命名和反馈。

**主要模块 / 文件**  
`src/screenshots/`

**主要链路**  
`Feature → ScreenshotWorkflow → mpv/file → result`

**实施重点**
先截图到 RuntimePaths screenshots；冲突命名和失败提示。

**基本验证**
截图成功/目录不可写。

**完成判断**  
用户可稳定截图。

### R11-02 A-B 循环

**目的**  
增加 A/B marker 和循环控制。

**主要模块 / 文件**  
`playback/.../ab_loop/` + Feature

**主要链路**  
`UI → typed command → mpv → state`

**实施重点**
先 set A/B/clear；媒体切换清空。

**基本验证**
正常区间/非法 A>B。

**完成判断**  
状态和后端一致。

### R11-03 画面比例

**目的**  
增加产品语义 aspect ratio。

**主要模块 / 文件**  
video adjustment feature

**主要链路**  
`preset/custom → domain → mpv adapter`

**实施重点**
先原始/16:9/4:3 等主预设。

**基本验证**
无视频/切换/reset。

**完成判断**  
不在 UI 保存 mpv raw string。

### R11-04 旋转与裁剪

**目的**  
增加 rotation/crop 独立职责。

**主要模块 / 文件**  
video adjustment/rotation、crop

**主要链路**  
`intent → validate → filter/option adapter`

**实施重点**
先 rotation，再 crop；复杂 filter chain 后补。

**基本验证**
reset/超界。

**完成判断**  
不会残留无效 filter。

### R11-05 倍速预设和精细调节

**目的**  
扩展 speed preset/step。

**主要模块 / 文件**  
speed policy + Feature

**主要链路**  
`input → speed command → snapshot`

**实施重点**
先 presets 和 +/- step；临时倍速可后补。

**基本验证**
min/max/reset。

**完成判断**  
显示与实际 speed 一致。

### R11-06 字幕样式

**目的**  
增加字体/字号/边框等主要字幕样式。

**主要模块 / 文件**  
settings subtitle style + adapter

**主要链路**  
`Settings → router → mpv subtitle props`

**实施重点**
先覆盖主要样式，不做完整 ASS 编辑器。

**基本验证**
字体缺失/reset。

**完成判断**  
设置持久化且运行时生效。

### R11-07 播放质量预设

**目的**  
把 hwdec/cache/scale 组合成产品级 preset。

**主要模块 / 文件**  
quality preset domain/policy

**主要链路**  
`preset → change router → backend`

**实施重点**
先 Auto/Quality/Performance 少量预设。

**基本验证**
切换/不支持项。

**完成判断**  
无半应用状态。

### R11-08 Shader 管理

**目的**  
支持本地 shader 注册、启用和失败恢复。

**主要模块 / 文件**  
shader registry/workflow + RuntimePaths

**主要链路**  
`shader files → registry → adapter → render`

**实施重点**
先单个/列表启停；排序/高级组合后补。

**基本验证**
缺文件/编译失败。

**完成判断**  
失败能安全禁用。

### R11-09 迷你播放器

**目的**  
建立独立 MiniPlayer window/screen，复用共享 Feature。

**主要模块 / 文件**  
mini player window/screen

**主要链路**  
`same Snapshot/Actions → Mini UI`

**实施重点**
不复制 PlaybackSession；只独立窗口几何/显示。

**基本验证**
切换/关闭/always-on-top。

**完成判断**  
主/迷你共享同一播放状态。

### R11-10 画中画可行性与平台实现

**目的**  
先验证 Windows PiP 可行路径，再决定实现。

**主要模块 / 文件**  
PiP ADR + platform port + screen

**主要链路**  
`feasibility → chosen platform path → same playback state`

**实施重点**
不可行也允许以明确 ADR 结束，不用 hack 冒充。

**基本验证**
真实 Windows 验证。

**完成判断**  
有稳定实现或明确不可行结论。

## 7. 框架打通后优先修复

- 高级功能互相堆进一个 AdvancedManager。
- 媒体切换后高级状态残留。
- Shader/filter 失败影响基础播放。
- Mini/PiP 创建第二 PlaybackSession。

## 8. 本阶段最小可运行里程碑

各高级功能可独立启用/关闭，不影响基础播放；至少截图、A-B、画面调整、Mini Player 等按计划逐项完成。

## 9. 阶段关闭条件

每个已实施能力都有真实主链和基本验证；未实施能力可以保持待办，不需要为了“阶段看起来完整”一次全部硬做。进入 R12 前只要求最终准备发布的能力集合明确。

## 10. 本阶段暂不要求

插件市场、在线 shader 市场、完整视频滤镜编辑器等不在 R11。

## 11. 后续扩展位置

未来新高级能力继续按独立 Feature/顶层模块加入；需要新线程/依赖时再提升规划强度。
