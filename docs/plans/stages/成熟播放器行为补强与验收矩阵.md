# 成熟播放器行为补强与验收矩阵

> 文档性质：R2–R13 跨阶段强制补充任务书  
> 生效时间：2026-08-07  
> 生效起点：R2-02 及之后尚未完成的 Atomic Task  
> 当前实施状态保护：不追溯重写 R2-01 已实现内容，也不改变其“源码构建 libmpv 包验收待完成”的现状  
> 参考项目：Screenbox `main` @ `20ff2f5ea0ee1651bdf96ab4224eb0aa428e9962`  
> 参考方式：只吸收成熟播放器的产品行为、状态边界、生命周期、竞态处理思路和验收场景，不复制 GPL-3.0 源码  
> 原有架构：Qt 6 + QML + C++20 + libmpv；PlaybackSession 单一播放真值；Presentation/Application/Domain/Infrastructure/Persistence/Platform 分层保持不变

# 0. 为什么现在补充

当前项目刚进入 R2，R2-01 仍处于 libmpv 固定包构建与本机验收阶段，`mpv_handle`、事件循环、PlaybackSession、Timeline、Playlist、Tracks、Resume 等核心职责尚未固化。这个时间点适合把成熟播放器已经验证过的高价值行为边界提前写入任务书，避免后续功能“能用但不完整”后再反向拆状态、补竞态、改调用链。

本补充不改变原任务书的产品范围，不把 Screenbox 的 UWP/LibVLCSharp 架构移植进本项目，也不新增生产依赖。它只做三件事：

1. 把成熟播放器常见的状态竞争、交互优先级和媒体切换边界变成明确的 Atomic Task；
2. 把 Timeline、Queue、Tracks、Controls、Resume 等功能从“主路径可用”提升到“成熟播放器行为完整”；
3. 为 R12/R13 提前定义可执行的回归矩阵，避免发布前才发现交互与生命周期缺口。

## 1.3 本项目架构继续优先

所有新增行为必须继续经过本项目既定主链：

```text
QML / Input / Platform event
        ↓
Presentation intent / Action
        ↓
Application workflow / PlaybackCommand
        ↓
PlaybackSession
        ↓
Infrastructure mpv adapter
        ↓
libmpv

libmpv event/property
        ↓
Mpv decoder
        ↓
PlaybackEvent
        ↓
PlaybackReducer
        ↓
PlaybackSnapshot
        ↓
ViewModel / Read-only model
        ↓
QML
```

任何新增功能如果要求 QML 直达 mpv、Playlist 改写播放真值、平台层读写 PlaybackSession 内部状态或 ViewModel 依赖具体 `MpvClient`，都视为架构失败，必须重新设计。

# 2. 跨阶段新增的核心状态模型

成熟播放器最容易出问题的地方不是“有没有一个枚举”，而是把多个不同原因变化的状态压进同一个枚举，最后出现组合爆炸。因此从 R3 开始必须显式区分以下状态轴；具体类型名可以结合实现调整，但语义边界必须存在。

## 2.1 Media Generation：媒体代际

每一次会替换当前媒体身份的加载请求都产生新的 `MediaGeneration`。

必须满足：

- generation 单调递增或使用不可复用唯一 token；
- A 媒体被 B 替换后，A 的 late event、late property、late command reply、late track/chapter refresh 不得写入 B 的快照；
- generation 在 PlaybackSession/Application 边界拥有，不交给 QML 自行生成；
- generation 不是 Playlist Entry ID；同一个 Playlist Entry 被重新加载也允许产生新 generation；
- generation 不是 mpv request userdata 的替代品，两者职责不同；
- shutdown 后所有 generation-scoped callback 只能 no-op，不得访问已销毁 Session。

示例：

```text
Load A → generation 41
Load B → generation 42
A 的 file-loaded / position / end-file / reply 晚到
event.generation = 41
currentGeneration = 42
→ discard
```

### 必须防住的具体路径

- Opening A 时立刻 Load B；
- A 已 file-loaded，但 UI 立即切 B；
- A end-file 与 B start-file 交错；
- A 的 seek/track command reply 晚于 B 的 load；
- A track-list/chapter-list 更新晚于 B；
- stop A 后立刻重新 load A；
- Playlist 自动下一项与用户手动选择下一项同时发生。

## 2.2 Request Identity：异步请求身份

所有需要结果关联的异步命令必须有 `RequestId`；媒体级命令还要绑定提交时的 generation。

要求：

- `RequestId` 唯一；
- `RequestTracker` 保存 request type、generation、提交时间和完成/取消状态；
- generation 变化时取消或失效旧 generation 的待完成请求；
- shutdown 时全部 pending request 进入 completed/cancelled，不留下悬空回调；
- unknown reply 只记录诊断，不改变状态；
- duplicate reply 不得二次应用副作用。

## 2.3 Playback Lifecycle：媒体生命周期

不要把所有交互、缓冲、播放状态塞进一个巨大状态枚举。至少要能表达：

- 无媒体；
- 正在打开/替换媒体；
- 当前媒体已建立；
- 当前媒体自然结束；
- 当前媒体失败；
- 正在卸载/关闭。

命名可调整，但必须能回答：**当前媒体身份是否有效、当前媒体是否仍在加载、是否已经结束/失败、旧媒体事件是否应被接受。**

## 2.4 Transport State：播放传输状态

独立表达：

- Playing；
- Paused；
- Stopped/Idle（根据最终模型确定）。

不得依赖控制栏按钮自己的 `isPlaying` 作为真值。

## 2.5 Buffering State：缓冲状态

Buffering 是可与“媒体已加载”“用户期望播放”等状态组合的独立维度。

至少需要：

- 是否处于 buffering；
- 可获得时保存 progress 百分比；
- buffering 开始/结束不能覆盖用户 Pause 意图；
- buffering overlay 不能覆盖 fatal error；
- buffering 结束后状态由 Snapshot 决定，不由 QML 猜测恢复成 Playing。

## 2.6 Interaction State：临时交互状态

以下状态属于 Presentation/Feature interaction，不进入 PlaybackSnapshot 播放真值：

- Scrubbing；
- Hover preview；
- 控制栏 hover；
- Popup/Menu open；
- Drawer open；
- 按键按下；
- 临时 HUD；
- Mouse captured；
- Modal active。

这些状态允许影响“是否自动隐藏控件”“Timeline 显示哪个位置”，但不能改写真实播放 position、track、pause 等后端真值。

# 3. R2 补强：libmpv 基础设施必须为后续成熟行为保留正确信息

R2-01 不返工。以下要求从 R2-02 起生效，并在 R2 阶段关闭前完成。

## R2-09：事件语义完整性与媒体边界信息

**目的**  
确保 R2 输出给 R3 的 typed event 足以构建可靠生命周期，而不是只保留“发生了某个事件”。

**归属**  
`src/playback/infrastructure/mpv/events/`

**要求**

- `start-file`、`file-loaded`、`end-file`、`shutdown`、`command-reply`、`property-change` 均保留上层判断所需的产品无关信息；
- `end-file` 必须保留 reason/error 等必要字段，能够区分 EOF、stop、error、redirect/next-file 等 libmpv 能提供的不同结束语义；
- decoder 不产生业务上的“自动下一项”决策；
- decoder 不持有当前媒体真值；
- raw `mpv_node` 生命周期必须在 infrastructure 内完全结束；
- node/字符串为空、缺字段、未知 event 均不得崩溃。

**验证**

- 正常 EOF；
- 用户 stop；
- load 失败；
- unknown event；
- property data 为 null/none；
- command reply success/error。

## R2-10：Property Baseline 完整化

在 R2-06 的 registry/observer 基础上，R3/R6/R8 明确需要的属性至少要有统一注册入口：

- position/time-pos；
- duration；
- pause；
- seekable；
- speed；
- volume；
- mute；
- buffering/cache 相关可稳定获得的产品所需属性；
- media title/path identity 所需属性；
- track-list；
- chapter-list；
- 当前 audio/subtitle/video track 选择状态；
- video params / audio-only 判断所需最小信息。

要求不是 R2 一次构建完整产品模型，而是禁止以后在 ViewModel、QML、Playlist 等位置散写 property 字符串。

## R2-11：Headless 行为探针扩展

在 R2-08 `playback_probe` 主链基础上增加以下脚本化步骤：

1. load → play → pause → seek → play → stop；
2. pause 状态 seek；
3. 连续两次不同 seek；
4. load A 后立即 load B，观察 A/B event 序列；
5. 自然 EOF 与用户 stop 的 end reason 区分；
6. 错误媒体 load；
7. shutdown during loading；
8. shutdown during playback。

R2 仍不实现 PlaybackSnapshot，但必须把真实事件序列记录出来，作为 R3 Reducer/GenerationGate 的测试输入依据。

# 4. R3 补强：PlaybackSession 从“单一真值”升级为“可抗乱序的单一真值”

## R3-09：MediaGeneration 与 Stale Event Gate

**目的**  
把“旧媒体事件不能污染新媒体”从验收口号升级成明确架构职责。

**建议归属**

```text
src/playback/domain/state/
  media_generation.*
src/playback/application/session/
  media_generation_gate.*
```

文件名可根据实际模块调整；如果 generation 逻辑足够小且与 Session 生命周期完全同责，可以保留在 Session 子模块，不强制机械拆文件。

**规则**

- 接受新的 replace-media/load 用例时创建 generation；
- 每个媒体级 request 记录提交 generation；
- Session 将可归属的 mpv 事件映射到当前/对应 generation；
- Reducer 只接受当前 generation 的媒体级事件；
- generation 更新本身必须是确定的 Session 操作，不由事件顺序猜测；
- stale event 可以进入诊断日志，但不得进入当前 Snapshot。

**硬验收**

- A→B 后 A 的 position 不改变 B；
- A→B 后 A 的 file-loaded 不把 lifecycle 改回 Loaded；
- A→B 后 A 的 end-file 不触发 B 的 Ended；
- A→B 后 A 的 track/chapter 不覆盖 B；
- A command reply 晚到不会影响 B。

## R3-10：PlaybackSnapshot 多轴状态

扩展 R3-02，不把所有状态压成一个 enum。

Snapshot 至少能够独立表达：

```text
media identity / generation
lifecycle
transport
buffering
position / duration / seekable
volume / mute / speed
media capabilities
audio/subtitle/video tracks
chapters
selected track ids
error
```

### Snapshot 不允许保存

- timeline thumb 当前像素；
- hover position；
- popup 是否打开；
- control bar opacity；
- mouse cursor hidden；
- list selection hover；
- transient HUD queue。

## R3-11：Reducer 清理矩阵

扩展 R3-03/R3-04，对以下转换建立纯单测：

| 输入转换 | 必须清理/替换 |
|---|---|
| Empty → Opening A | 上一媒体全部 media-scoped state |
| Loaded A → Opening B | A tracks/chapters/duration/selected track/error/buffer state |
| Any → Stop/Unload | position/duration/seekability/tracks/chapters 等按最终 stop 语义处理 |
| Any → Failed | 保留可诊断媒体 identity；清理不再可信的 active state |
| Any → Ended | position/end state 一致；不能误清 Playlist current entry |
| generation N → N+1 | N 的后续 media-scoped event 全部失效 |

具体 stop 后是否保留“当前媒体信息”由产品语义在 R3 冻结，但必须有唯一规则，禁止不同 ViewModel 各自清理一部分。

## R3-12：Supersession / Cancellation

针对会被新请求替代的操作建立 supersession 规则：

- Load A 被 Load B 替代；
- Seek 1 被 Seek 2 替代；
- track select A 被同类 track select B 替代；
- shutdown 替代全部普通命令。

不是所有命令都必须物理取消 mpv 执行，但上层必须知道旧结果已经失效，旧 reply 不能产生新副作用。

# 5. R6 补强：Timeline、Controls、HUD 与播放器输入完整化

Screenbox 的 SeekBar 证明成熟 Timeline 实际包含 position 同步、scrub ownership、paused seek、buffering、chapter、resume 等多条边界。本项目不复制其实现，而是将这些行为拆回独立职责。

## R6-13：Timeline Interaction State Machine

扩展 R6-06。

**建议状态**

```text
Idle
Hovering
Scrubbing
CommitPending
Cancelled
Disabled
```

不要求机械使用这个 enum，但必须有等价状态语义。

### 数据必须分成两份

```text
actualPosition   ← PlaybackSnapshot，只读真值
previewPosition  ← Timeline Interaction 临时值
```

规则：

- Idle 时 thumb 跟随 `actualPosition`；
- Pointer press 进入 Scrubbing 后，thumb/时间标签只跟 `previewPosition`；
- Scrubbing 期间后台 position 更新仍可进入 Snapshot，但不能抢回 thumb；
- Pointer release/commit 只提交一次最终 Seek；
- cancel 不发送最终 Seek，UI 回到最新 actual position；
- 媒体 generation 改变立即取消当前 scrub；
- seekable=false 时不能进入有效 Scrubbing；
- duration 未知/无穷/live 时不能制造虚假百分比 Seek；
- seek command 被拒绝/失败后回到 Snapshot 真值并给出反馈；
- paused/buffering 状态下 Seek 仍必须有明确行为；
- Ended 后拖回前部时，是否恢复到 Paused/Playing 由 PlaybackSession 产品规则决定，Timeline 不自行 replay。

### Seek 提交策略

必须区分：

- drag preview：不持续提交最终 seek；
- drag commit：一次最终 seek；
- keyboard/wheel relative seek：允许 debounce/coalesce，但最终状态由 Snapshot 回写；
- chapter seek：直接走统一 Seek action；
- HUD seek：只显示结果，不成为 position owner。

### R6 Timeline 强制测试矩阵

- Playing drag；
- Paused drag；
- Buffering drag；
- drag → cancel；
- drag → media switch；
- drag → window focus loss；
- seek to 0；
- seek to duration/end；
- Ended → seek earlier；
- 10 次快速键盘 Seek；
- 连续滚轮 Seek；
- chapter seek；
- non-seekable live；
- unknown duration；
- seek command failure。

## R6-14：Controls Visibility Policy

R6-09 不再只是“一个 inactivity timer”。建立独立控制栏显隐策略，输入为交互状态，输出为 `Visible / Fading / Hidden` 或等价语义。

### 默认必须保持可见

- 无媒体；
- Paused（除非之后明确产品选择不同策略）；
- Error；
- 鼠标位于控制栏；
- Timeline Scrubbing；
- Popup/Menu/Drawer 打开；
- 键盘焦点正在播放器控件内；
- 用户刚完成有效输入的一段超时窗口内。

### 允许自动隐藏

- Playing；
- 无 popup/menu/modal；
- 无 scrub；
- 无 hover/focus 保持条件；
- inactivity timeout 到达。

### 必须验证

- Popup 打开时 timer 到期不能隐藏；
- scrub 时 timer 到期不能隐藏；
- popup 关闭后重新计算 timeout；
- mouse move 恢复控制栏；
- keyboard action 恢复控制栏或显示 HUD；
- fullscreen/windowed 行为一致；
- Error overlay 出现时控制栏策略不抖动；
- 快速 pause/play 不产生两个 timer owner。

## R6-15：Cursor Visibility Policy

R6-10 必须独立于 control opacity，但可以消费同一 Interaction Snapshot。

- popup/menu/modal 时 cursor 强制可见；
- scrubbing/drag 时可见；
- hidden controls + playing + inactivity 才允许隐藏；
- window leave/focus loss/activation restore 后必须恢复到可解释状态；
- shutdown 前不需要“恢复系统全局鼠标”，只能恢复本窗口 override/cursor state；
- 不允许多个 QML 子控件分别开 timer 争抢 cursor。

## R6-16：HUD Coalescing

R6-12 增加消息合并键：

- Volume 连续变化合并成同一个 HUD；
- Seek 连续变化合并；
- Speed 连续 +/- 合并；
- Track change 不与 Volume 合并；
- Error/重要状态不得被低优先级 HUD 覆盖；
- HUD queue 有最大长度或覆盖策略，禁止无限积压。

# 6. R7 补强：Play Queue 从“列表功能”升级为“独立运行状态”

Screenbox 的价值在于把队列可观察状态和队列协调逻辑分开，并集中处理当前项、Shuffle、Repeat、Next/Previous、EOF 和异步更新。本项目保留自己的 Domain/Application 分层，不复制 Coordinator 类，但必须获得同等清晰的状态所有权。

## R7-10：Queue Snapshot 与稳定身份

Playlist/Queue 的权威状态至少包含：

- ordered entries；
- stable `EntryId`；
- current `EntryId`；
- current index（建议从 EntryId + order 推导或在 mutation 后统一重算，不能成为第二真值）；
- Repeat mode；
- Shuffle mode；
- 可选 original-order/shuffle bookkeeping，仅在真正实现 shuffle 时创建；
- navigation capability：CanNext / CanPrevious 可由 policy 推导。

### 明确禁止

- QML ListView index 作为 current media identity；
- PlaybackSnapshot 自己维护另一份 Playlist；
- 删除/重排后 currentIndex 与 currentId 各写各的；
- Shuffle 模式下复制两份都可写列表；
- ViewModel 直接改 Observable/ListModel 再“通知 Controller”。

## R7-11：Queue Mutation 原子语义

每个 mutation 必须定义输入、输出和 current 行为：

- append；
- insert；
- remove non-current；
- remove current；
- reorder non-current；
- reorder current；
- clear；
- replace queue；
- select current；
- next；
- previous；
- repeat mode change；
- shuffle on/off。

### 删除当前项

R7-09 要在实现前冻结策略，至少明确：

- 队列仅 1 项时：停止/卸载并 current=null；
- 中间 current 被删除：选择下一个还是上一个；
- 最后一项 current 被删除：是否选择前一项；
- 删除动作与 PlaybackSession load/stop 的调用顺序；
- load 失败时是否保留 current identity。

不在补充任务书中替用户决定 UX，但禁止实现时“顺手选择一个行为”而没有测试。

## R7-12：Auto Advance 幂等与竞态

自然 EOF、用户 Next、媒体切换可能同时发生。

必须保证：

- 每个媒体 generation 的自然 EOF 最多触发一次 auto-advance；
- 用户 Stop 不触发 auto-advance；
- stale generation EOF 不触发 auto-advance；
- 用户已经手动选择 B 后，A late EOF 不再次跳 C；
- Repeat One 不通过建立第二个 Playlist current 来实现；
- Repeat All 在最后一项有确定行为；
- Shuffle 下 current entry identity 不丢失；
- 连续 Next/Previous 使用统一 navigation policy，不产生双 load。

## R7-13：异步 Media Open Supersession

文件解析、URL 打开、playlist parse 等异步工作必须可被更新请求替代。

示例：

```text
Open A（异步解析中）
Open B
A 解析完成
→ A 结果失效，不覆盖 B queue/current
```

要求：

- MediaOpenCoordinator 为每次 open workflow 生成 operation identity；
- 新 replace-open 取消或失效旧 operation；
- async parser 返回结果前检查 operation identity；
- QML drawer/model 不直接承担取消职责；
- shutdown 取消未完成 open operation。

## R7-14：Queue UI 状态解耦

必须同时允许以下状态不同：

- current playing item；
- keyboard focus item；
- selected item；
- hover item；
- invalid/unavailable item；
- pending loading item。

一个蓝色 selection/focus 状态不能同时代表“正在播放”。状态视觉在 R5/R6 design token 基础上明确区分。

# 7. R8 补强：Tracks / Subtitles / Chapters 生命周期完整性

## R8-09：Track List Generation Scope

- 每个 track list 属于当前 media generation；
- 媒体替换先清旧列表，再接新列表；
- stale generation track-list 丢弃；
- list item 使用 backend stable ID，不使用视觉 index 作为命令参数；
- selected track ID 不存在于新列表时必须回到明确的 none/default 状态；
- selection command failure 不允许 UI 假选中；
- subtitle off 是正式状态，不用“选择不存在的 index”模拟；
- audio/video/subtitle 三类轨道状态分离。

## R8-10：Track Selection Request Arbitration

连续快速切换字幕/音轨时：

- 后一次同类选择 supersede 前一次；
- command reply 与提交 generation/request id 关联；
- UI 可以显示 pending，但最终 selected 只来自 Snapshot；
- media switch 取消所有旧 track-selection pending state。

## R8-11：External Subtitle Idempotency

外挂字幕 workflow 必须处理：

- 同一路径重复添加；
- 不同路径但后端判定重复；
- 文件删除/不可读；
- unsupported/parse error；
- 加载成功但 track refresh 延迟；
- media switch during load；
- shutdown during load。

成功后的外挂字幕必须进入同一 TrackDescriptor 模型，不允许 QML 维护额外“外挂字幕列表”。

## R8-12：Chapter 与 Timeline 单向协作

- Chapter list 属于 current generation；
- 点击 chapter 只产生统一 Seek action；
- Timeline 只从 Snapshot position 更新；
- chapter marker 是 Timeline 的只读投影；
- 无章节媒体必须清空 marker；
- chapter title 缺失有统一 fallback；
- chapter start 超出有效 duration 时由 decoder/domain validation 处理，不让 QML 自己纠正。

# 8. R9 补强：Resume/Progress 必须与当前媒体代际对齐

Screenbox 的进度恢复链说明 Progress Tracking 不是简单“每 N 秒写 position”。本项目继续使用自己的 Persistence/History 架构，但增加以下强制边界。

## R9-10：Progress Recorder Generation Guard

写入条件至少检查：

- 当前有有效 MediaIdentity；
- 当前 Snapshot generation 仍是 recorder 观察的 generation；
- position/duration 数据有效；
- 非临时 previewPosition；
- 非 stale event；
- 当前策略允许保存该媒体类型。

保存触发：

- 周期节流；
- pause；
- stop/unload；
- media replacement；
- application close。

禁止：

- 每个 position event 写库；
- scrub preview 写库；
- 旧 generation 在 B 已打开后覆盖 B/A 的最新进度；
- DB write failure 阻塞 Playback Thread。

## R9-11：Resume Once Per Generation

恢复位置必须作为一个明确 workflow：

1. 当前 media identity 已知；
2. history query 完成；
3. 当前 generation 仍未被替换；
4. duration/seekability 达到策略需要的可判定状态；
5. resume policy 计算目标；
6. 每个 generation 最多自动恢复一次；
7. 通过统一 Seek command 提交；
8. 失败只影响恢复，不使媒体加载失败。

### 不恢复场景

- live / non-seekable；
- history position 小于最小阈值；
- near-end/completed；
- duration 明显变化导致历史位置非法；
- 用户在恢复前已经主动 Seek；
- generation 已变化。

具体阈值在 R9 冻结为配置/策略常量并测试，不散落在 QML。

---

# 9. R10 补强：所有输入与系统媒体控制走同一个 Action 语义

## R10-10：Input/Action Convergence

Action Registry 建立后，以下入口必须汇合到同一个 ActionId/handler：

- QML 按钮；
- keyboard shortcut；
- mouse shortcut/double click；
- wheel seek/volume；
- system media keys；
- Mini Player 控件（R11）；
- 可行时的 PiP 控件。

同一个 PlayPause 行为不得有 4 套调用链。

## R10-11：System Transport State Synchronization

系统媒体控制不只接收按键，还必须从产品状态更新自身能力：

- play/pause state；
- CanNext；
- CanPrevious；
- Repeat mode（平台允许时）；
- 当前媒体标题/元信息（平台允许且属于 MVP 时）；
- 无媒体/错误/关闭时清理。

要求：

- 平台回调只产生 Action/Intent，不直接改 Playlist 或 mpv；
- 平台对象订阅在明确 owner 中建立和解除；
- Session/窗口关闭后不得继续收到可访问已销毁对象的回调；
- UI、快捷键、系统媒体键的 enable/disable 规则来源一致。

---

# 10. R11 补强：Mini Player / PiP 必须是同一播放器的第二视图

## R11-11：Shared Playback Surface Contract

Mini Player/PiP 只能拥有：

- 独立窗口几何；
- always-on-top/window mode；
- 自己的 QML presentation interaction；
- 必要的 render surface 生命周期。

不得拥有：

- 第二个 PlaybackSession；
- 第二份 Playlist 真值；
- 第二份当前媒体；
- 第二份 Track/Resume 状态。

主窗口 ↔ Mini/PiP 切换必须验证：

- 正在播放；
- paused；
- buffering；
- fullscreen 退出；
- media switch；
- close mini；
- close main；
- application shutdown。

Render 资源可以因窗口变化重建，但 PlaybackSession 不因切换窗口重新加载媒体。

# 11. R12 补强：成熟播放器行为回归矩阵

新增 R12-13，作为 R13 之前的强制阶段门禁。

## R12-13：Mature Player Behavior Matrix

### A. Media Switching / Generation

| 场景 | 通过条件 |
|---|---|
| Opening A → Load B | A 所有后续媒体级状态不写入 B |
| Loaded A → Load B → A EOF late | 不自动跳过 B |
| A seek reply late after B load | 不改 B position/pending state |
| A track-list late after B load | B track list 不被覆盖 |
| A error late after B loaded | B 不显示 A error |
| B load fails | A 是否保留/卸载按既定 replace policy 一致，不出现混合状态 |

### B. Timeline / Seek

| 场景 | 通过条件 |
|---|---|
| Playing drag | thumb 由 preview 接管，不抖回 |
| Paused drag | 可提交 seek；pause 语义不丢失 |
| Buffering drag | 行为确定，不产生互相覆盖状态 |
| drag cancel | 不提交最终 seek |
| drag + media switch | scrub 取消，新媒体从真实 position 开始 |
| seek 0 | 到达起点，无负数 |
| seek end | 按产品 Ended/Playing 规则稳定 |
| Ended → seek earlier | 可解释恢复，不依赖 QML replay hack |
| rapid keyboard/wheel seek | coalesce/debounce 后状态准确 |
| chapter seek | 只有一条 Seek 链 |
| live/non-seekable | 控件禁用/受限，不制造假 Seek |
| unknown duration | 不除零、不显示错误百分比 |

### C. Queue

| 场景 | 通过条件 |
|---|---|
| remove non-current | current identity 不变 |
| remove current middle | 按冻结策略选择下一状态 |
| remove current only item | current 清空且 Playback 协调一致 |
| reorder current | current 仍指向同一 EntryId |
| toggle shuffle | current 不丢；恢复顺序符合策略 |
| repeat one EOF | 不产生双 load |
| repeat all tail EOF | 回到正确 entry |
| user Next + EOF 同时 | 最多一次有效推进 |
| rapid Next x10 | 最终 current 与加载 generation 一致 |
| queue replace during async parse | 旧 parse 结果不覆盖新 queue |

### D. Tracks / Subtitles / Chapters

- A→B 轨道整体替换；
- track selection failure；
- rapid subtitle cycle；
- subtitle off；
- external subtitle duplicate；
- external subtitle load + media switch；
- no chapters → chapters；
- chapters → no chapters；
- chapter seek while paused；
- stale chapter update after media switch。

### E. Controls / Input

- playing inactivity auto-hide；
- paused controls remain available；
- popup/menu prevents hide；
- scrub prevents hide；
- mouse move restores；
- keyboard action produces consistent HUD/visibility；
- cursor state follows popup/scrub/focus；
- fullscreen/windowed transition；
- text input shortcut protection；
- system media key and QML button produce same Action result。

### F. Resume / Persistence

- progress save during long playback；
- pause flush；
- media replacement flush；
- close flush；
- DB locked；
- DB read-only；
- near-end media not wrongly resumed；
- live media not resumed；
- user seeks before resume query completes；
- A resume query returns after B loaded；
- corrupted history row does not crash playback。

### G. Shutdown

必须分别测试从以下状态关闭：

- Empty；
- Opening；
- Playing；
- Paused；
- Buffering；
- Scrubbing；
- Popup open；
- External subtitle loading；
- Queue parse/loading；
- DB write pending；
- Mini Player active；
- Fullscreen。

通过条件：

- 无 deadlock/UAF/crash；
- callback 解绑；
- request 被取消/失效；
- Render 在 mpv handle 前释放；
- DB flush 有界；
- Playback Thread、DB Thread、平台监听无残留。

# 14. 模块化落地约束

为了防止补强任务反而制造新“Manager 大文件”，新增职责按以下边界落位：

```text
src/playback/
├─ domain/state/                    # generation、snapshot、reducer/invariants
└─ application/
   ├─ session/                      # session lifecycle + media generation gate
   └─ requests/                     # request identity/supersession

src/presentation/
├─ viewmodels/player/
└─ qml/features/player/
   ├─ timeline/                     # timeline visual + interaction adapter
   ├─ chrome/                       # controls visibility presentation
   ├─ volume/

src/playlist/
├─ domain/                          # queue state/navigation policy
├─ application/                     # mutations/auto-advance/open coordination
└─ presentation/                    # readonly model + UI intents

src/tracks/
├─ domain/
├─ application/
└─ presentation/

src/history/
├─ domain/

src/shortcuts/
```
