# Qt6 + libmpv 播放器阶段实施任务书

> 版本定位：快速框架实施版  
> 范围：R2–R14  
> 原则：先把正确的模块框架和真实主链跑起来，再集中修复、补边界和做强验证。  
> 不包含：R0、R1；现有 R0/R1 状态不在本包中重新定义。

## 统一执行策略

本任务书不要求每个 Atomic Task 都先写成“工程合同”。普通任务只要明确目标、模块、主链、实现重点和基本验证即可直接开工。

整个项目按四个节奏推进：

1. **骨架优先**：先建立真正会被使用的目录、CMake、接口、对象所有权和最小实现，不创建大批空文件。
2. **主链优先**：优先让真实链路工作，例如 `libmpv → PlaybackSession → Render → ViewModel → QML`，先看到结果。
3. **边做边修**：编译错误、接口不顺、职责耦合、明显竞态、真实运行问题出现后立即在影响边界修复；普通边缘问题可记录到阶段修复清单，不要求每个小任务都阻断后续。
4. **集中硬化**：R12 专门负责压力、故障、性能、泄漏、长时间运行和最终架构审查；R13 再做真正发布门禁。

只有以下问题默认视为“必须先停下来解决”的硬阻断：

- 项目无法 configure/build；
- 主链完全不可运行；
- 明确的状态双重拥有、循环依赖或错误模块边界；
- crash、deadlock、use-after-free、线程越界等高风险生命周期问题；
- 数据损坏、不可逆迁移错误；
- Render/mpv 销毁顺序错误；
- 发布阶段安装包无法在干净机器启动。

普通 UI 细节、非主路径边缘场景、尚未覆盖的手工矩阵不需要阻止每个 Atomic Task 继续，但必须在阶段修复清单或 R12/R13 前关闭。

## 模块化总原则

- 一个模块只拥有一个清晰职责；新能力有独立状态、IO、生命周期、错误或测试边界时再拆文件/目录。
- 不为了“文件多”而拆；也不为了“改得少”把不同职责继续塞进同一个文件。
- QML 不直接调用 libmpv；PlaybackSession 是播放真值；Playlist 只拥有队列；DatabaseWorker 只拥有数据库连接；Renderer 只拥有 Render/OpenGL 资源。
- 所有源码/配置/行为变化继续同步记录根 `README.md`。
- R0-06 已按用户要求跳过，因此依赖合法可分发媒体 fixture 的验证，如果只有本地合法样本，必须写成“本地验证”，不能伪装成完整 fixture 体系已经闭环。

# Stage R9：历史、恢复播放与设置

## 1. 本阶段最终要得到什么

给播放器加入“记忆”：数据库线程、迁移、最近播放、进度恢复和设置。R9 之后应用具备真正日常使用需要的持久化能力。

## 2. 本阶段怎么快速推进

先搭 DatabaseWorker + Migration，让数据库主链可用；随后接 History/Resume，再接 Settings。先保存最必要字段，不要一开始设计复杂 schema。真实使用问题出现后再追加 migration。

## 3. 目标模块结构

```text
src/persistence/
├─ database/
├─ migrations/
├─ repositories/
└─ mapping/
src/history/
src/settings/
src/presentation/qml/features/settings/
```

## 4. 阶段主链

```text
PlaybackSnapshot / Settings intent
  ↓
History / Settings application workflow
  ↓
Repositories
  ↓
DatabaseWorker (DB Thread)
  ↓
SQLite
```

## 5. 关键状态/资源归属

- SQLite connection：DatabaseWorker。
- History 业务语义：History module。
- Settings 真值：SettingsController + repository。
- QML：只读 ViewModel + intent。

## 6. Atomic Tasks

### R9-01 Database worker

**目的**  
先把 SQLite 连接和任务队列放到独立线程。

**主要模块 / 文件**  
`persistence/database/`

**主要链路**  
`application task → DB queue → DB thread → result`

**实施重点**
先实现 open/query/write/flush/close；仓储随后接。

**基本验证**
线程归属、写入、关闭 flush。

**完成判断**  
UI 播放线程不直接阻塞 SQL。

**高风险约束**
QSqlDatabase connection 只能在所属线程创建/使用/销毁；关闭必须有界，不能无限等待。

### R9-02 Migration 001

**目的**  
建立首版 schema 和 migration registry。

**主要模块 / 文件**  
`persistence/migrations/`

**主要链路**  
`startup → schema version → transaction migration → ready`

**实施重点**
先创建 history/settings 必要表；saved playlist 可按实际阶段加入。

**基本验证**
新库、重复启动、故意失败 rollback。

**完成判断**  
schema 可重复启动且失败不半迁移。

**高风险约束**
发布后的 migration 内容不可修改；失败必须 rollback，不允许半迁移继续运行。

### R9-03 History repository

**目的**  
提供播放历史读写。

**主要模块 / 文件**  
sqlite_history_repository + mapper

**主要链路**  
`history domain ↔ repository ↔ DB worker`

**实施重点**
先 upsert/query；清理和损坏行后补。

**基本验证**
写/查/坏行。

**完成判断**  
上层不碰 SQL row。

### R9-04 Progress persistence workflow

**目的**  
节流保存 position。

**主要模块 / 文件**  
history_recorder + policy

**主要链路**  
`Snapshot position → throttle → repository`

**实施重点**
先每 N 秒 + pause/stop/close flush；真实使用后调策略。

**基本验证**
持续播放/pause/close。

**完成判断**  
不会每帧写库。

### R9-05 Resume policy/workflow

**目的**  
重新打开媒体时恢复合理位置。

**主要模块 / 文件**  
resume policy/query/workflow

**主要链路**  
`MediaIdentity → history → policy → Seek`

**实施重点**
先阈值规则；提示/自动方式由设置控制。

**基本验证**
短片/near-end/completed。

**完成判断**  
不会从结尾误恢复。

### R9-06 Recent media

**目的**  
建立最近播放列表。

**主要模块 / 文件**  
recent query/model

**主要链路**  
`DB → recent model → MediaOpenCoordinator`

**实施重点**
失效路径保留并标记。

**基本验证**
排序/失效路径。

**完成判断**  
最近列表可重新打开媒体。

### R9-07 Settings repository

**目的**  
持久化产品设置。

**主要模块 / 文件**  
sqlite_settings_repository + mapper

**主要链路**  
`SettingsSnapshot ↔ JSON value ↔ DB`

**实施重点**
先保存当前真正存在的设置；未知/坏值回默认。

**基本验证**
default/corrupt value。

**完成判断**  
坏设置不崩启动。

### R9-08 Settings Controller

**目的**  
统一设置真值和应用时机。

**主要模块 / 文件**  
settings_controller + change_router

**主要链路**  
`QML intent → controller → apply/persist`

**实施重点**
先分 immediate / next-media / restart 三类；render rebuild 有需要再加。

**基本验证**
修改/失败/重启要求。

**完成判断**  
QML 不直接写数据库。

### R9-09 Settings UI

**目的**  
做可扩展的设置页。

**主要模块 / 文件**  
qml/features/settings/ + settings VM

**主要链路**  
`settings snapshot ↔ controls → controller`

**实施重点**
一个 row 一个概念；先完成 MVP 设置，再扩展。

**基本验证**
默认、修改、恢复。

**完成判断**  
设置页可用且不变成大单文件。

## 7. 框架打通后优先修复

- DB locked/不可写。
- 关闭 flush。
- 高频 position 写入。
- near-end resume。
- 损坏设置回退。
- migration 失败 rollback。

## 8. 本阶段最小可运行里程碑

关闭再启动应用后，最近播放、进度和设置仍存在；播放主线程不被数据库明显卡住。

## 9. 阶段关闭条件

数据库线程边界正确；migration 可重复启动；核心历史/设置可用；持久化失败不会让播放器核心崩溃。更复杂 schema 和极端故障由 R12 强化。

## 10. 本阶段暂不要求

云同步、账号、多设备同步不在 R9。

## 11. 后续扩展位置

未来云同步单独 `sync`，只通过 repository/domain 接口与本地状态协作。
