# Qt6 + libmpv 播放器阶段实施任务书

> 版本定位：快速框架实施版  
> 范围：R2–R14  
> 原则：先把正确的模块框架和真实主链跑起来，再集中修复、补边界和做强验证。  
> 不包含：R0、R1；现有 R0/R1 状态不在本包中重新定义。

## 统一执行策略

本任务书不要求每个 Atomic Task 都先写成“工程合同”。普通任务只要明确目标、模块、主链、实现重点和基本验证即可直接开工。

整个项目按四个节奏推进：

1. **骨架优先**：先建立真正会被使用的目录、CMake、接口、对象所有权和最小实现，不创建大批空文件。
2. **主链优先**：优先让真实链路工作，例如 `libmpv → PlaybackSession → Render → ViewModel → QML`，先看到结果。
3. **边做边修**：编译错误、接口不顺、职责耦合、明显竞态、真实运行问题出现后立即在影响边界修复；普通边缘问题可记录到阶段修复清单，不要求每个小任务都阻断后续。
4. **集中硬化**：R12 专门负责压力、故障、性能、泄漏、长时间运行和最终架构审查；R13 再做真正发布门禁。

只有以下问题默认视为“必须先停下来解决”的硬阻断：

- 项目无法 configure/build；
- 主链完全不可运行；
- 明确的状态双重拥有、循环依赖或错误模块边界；
- crash、deadlock、use-after-free、线程越界等高风险生命周期问题；
- 数据损坏、不可逆迁移错误；
- Render/mpv 销毁顺序错误；
- 发布阶段安装包无法在干净机器启动。

普通 UI 细节、非主路径边缘场景、尚未覆盖的手工矩阵不需要阻止每个 Atomic Task 继续，但必须在阶段修复清单或 R12/R13 前关闭。

## 软件可用性里程碑

| 里程碑 | 达到的实际形态 |
|---|---|

| R13 | 可发给别人安装使用的 Windows 正式桌面软件 |

## 模块化总原则

- 一个模块只拥有一个清晰职责；新能力有独立状态、IO、生命周期、错误或测试边界时再拆文件/目录。
- 不为了“文件多”而拆；也不为了“改得少”把不同职责继续塞进同一个文件。
- QML 不直接调用 libmpv；PlaybackSession 是播放真值；Playlist 只拥有队列；DatabaseWorker 只拥有数据库连接；Renderer 只拥有 Render/OpenGL 资源。
- 所有源码/配置/行为变化继续同步记录根 `README.md`。
- R0-06 已按用户要求跳过，因此依赖合法可分发媒体 fixture 的验证，如果只有本地合法样本，必须写成“本地验证”，不能伪装成完整 fixture 体系已经闭环。

# Stage R6：播放器主界面与基础交互

## 1. 本阶段最终要得到什么

把前面的 Core、Render、Design System 组装成一个真正可以操作的播放器窗口。R6 完成时，用户已经可以把它当“基础桌面播放器”使用。

## 2. 本阶段怎么快速推进

优先顺序：PlayerScreen 骨架 → 视频 → 底部控制 → transport → timeline → volume → fullscreen。先让核心操作能用，再补自动隐藏、鼠标、Overlay、HUD 的体验问题。

## 3. 目标模块结构

```text
src/presentation/
├─ viewmodels/player/
└─ qml/screens/player/
   ├─ PlayerScreen.qml
   ├─ layout/
   ├─ overlays/
   ├─ drawers/
   └─ states/
src/presentation/qml/features/player/
├─ transport/
├─ timeline/
├─ volume/
└─ chrome/
```

## 4. 阶段主链

```text
PlaybackSnapshot
  ↓
Player / Feature ViewModels
  ↓
QML Controls
  ↓ intent
Action / PlaybackCommandBus
  ↓
PlaybackSession
```

## 5. 关键状态/资源归属

- 真实播放状态：PlaybackSnapshot。
- scrub 临时预览：Timeline interaction/session。
- hover/pressed/popup：QML/presentation。
- fullscreen 窗口状态：window controller。

## 6. Atomic Tasks

### R6-01 PlayerScreen 组合骨架

**目的**  
先把播放器页面结构搭出来，但保持它只是组合层。

**主要模块 / 文件**  
`screens/player/PlayerScreen.qml`、`layout/overlays/drawers/states/`

**主要链路**  
`PlayerViewModel → PlayerScreen → child features`

**实施重点**
先组合 VideoViewport、Top/BottomRegion、OverlayStack、DrawerHost。

**基本验证**
窗口加载和基本 resize。

**完成判断**  
页面结构清晰，没有把所有按钮和业务塞回一个文件。

### R6-02 视频 viewport

**目的**  
把 R4 MpvVideoItem 放进实际播放器布局。

**主要模块 / 文件**  
`layout/VideoViewport.qml`

**主要链路**  
`snapshot/media capability → viewport → MpvVideoItem`

**实施重点**
处理空媒体、纯音频和 aspect fit。

**基本验证**
空/音频/视频三种状态。

**完成判断**  
视频成为第一视觉主体。

### R6-03 顶部区域

**目的**  
建立标题、窗口按钮、精简元数据。

**主要模块 / 文件**  
`PlayerTopRegion.qml` + title/window feature

**主要链路**  
`metadata/window state → top bar`

**实施重点**
优先完成可用和布局；后续再打磨 hover/动画。

**基本验证**
长标题、fullscreen。

**完成判断**  
窗口可正常拖动/控制（平台细节 R10）。

### R6-04 底部控制区域

**目的**  
把 transport/timeline/volume/actions 放进独立区域。

**主要模块 / 文件**  
`PlayerBottomRegion.qml`

**主要链路**  
`child feature controls → bottom layout`

**实施重点**
只组合，不内联各 feature 实现；窄窗口先有基本溢出策略。

**基本验证**
常见窗口宽度。

**完成判断**  
主要控制完整出现。

### R6-05 Transport ViewModel 和 Controls

**目的**  
真正连接 play/pause/stop/prev/next。

**主要模块 / 文件**  
transport VM + QML controls

**主要链路**  
`Snapshot → VM → Control → Action/CommandBus`

**实施重点**
先完成 play/pause/stop；prev/next 在 Playlist 可用后启用。

**基本验证**
按钮状态与真实播放对应。

**完成判断**  
用户可完成基础 transport。

### R6-06 Timeline ViewModel 和 scrub session

**目的**  
先解决进度显示和可拖动 Seek。

**主要模块 / 文件**  
timeline VM / scrub session / QML

**主要链路**  
`Snapshot actual position ↔ scrub preview → one Seek`

**实施重点**
拖动时 preview 暂时接管 thumb；commit 一次 Seek；媒体切换取消 scrub。

**基本验证**
拖动、取消、commit、non-seekable。

**完成判断**  
Timeline 不抖回。

### R6-07 Volume

**目的**  
把音量、滚轮、mute 和 HUD 串起来。

**主要模块 / 文件**  
volume VM + QML

**主要链路**  
`Snapshot volume/mute → UI → command → HUD`

**实施重点**
先支持 slider+mute；滚轮和合并消息随后补。

**基本验证**
mute/unmute/slider。

**完成判断**  
UI/backend/HUD 一致。

### R6-08 Fullscreen

**目的**  
建立 fullscreen、Esc、双击入口。

**主要模块 / 文件**  
fullscreen VM/state

**主要链路**  
`intent → window controller → state`

**实施重点**
先用 Qt 通用窗口能力；Win32 细节留 R10。

**基本验证**
进入/退出/Esc/双击。

**完成判断**  
全屏基本稳定。

### R6-09 控制栏自动隐藏

**目的**  
让播放器开始有沉浸感。

**主要模块 / 文件**  
auto-hide timer/policy

**主要链路**  
`interaction states → chrome visibility`

**实施重点**
先做简单 inactivity timer；菜单、scrub、pause 等例外随后修。

**基本验证**
播放/暂停/menu/scrub。

**完成判断**  
不会频繁误隐藏。

### R6-10 鼠标隐藏

**目的**  
把 cursor 隐藏与控制栏和弹层协调。

**主要模块 / 文件**  
CursorVisibilityController

**主要链路**  
`interaction → cursor policy`

**实施重点**
先复用 auto-hide 状态，再补弹窗/无障碍例外。

**基本验证**
播放/菜单/拖动。

**完成判断**  
沉浸模式下鼠标能正确隐藏/恢复。

### R6-11 状态 overlay

**目的**  
建立 Loading/Buffering/Ended/Error。

**主要模块 / 文件**  
PlayerStatusOverlay + selector

**主要链路**  
`PlaybackSnapshot → visual state → overlay`

**实施重点**
先做互斥优先级和基本文案；视觉继续迭代。

**基本验证**
四类状态切换。

**完成判断**  
用户知道播放器当前发生什么。

### R6-12 HUD 消息队列

**目的**  
建立音量/Seek/倍速/轨道的短反馈。

**主要模块 / 文件**  
HudMessageQueue + PlayerHudOverlay

**主要链路**  
`action result → message → display/timeout`

**实施重点**
先支持基本队列/超时；同类消息合并后补。

**基本验证**
连续 volume/seek。

**完成判断**  
HUD 不刷屏。

## 7. 框架打通后优先修复

- PlayerScreen 过度膨胀。
- Timeline 拖动被后台 position 拉回。
- fullscreen/auto-hide/popup 状态互相打架。
- HUD 消息刷屏。
- 长标题和窄窗口布局。

## 8. 本阶段最小可运行里程碑

打开媒体后能看到视频；播放/暂停；拖进度；调音量/静音；全屏；Loading/Buffering/Error 有可见反馈。

## 9. 阶段关闭条件

基础操作主链稳定；没有 QML 直接 mpv；PlayerScreen 仍以组合为主。视觉微调和极端尺寸可以继续迭代，不必阻断 R7。

## 10. 本阶段暂不要求

Playlist/Tracks/Settings 的完整 UI 不在 R6；Win32 hit-test/DWM/媒体键留 R10。

## 11. 后续扩展位置

Mini Player/PiP 在 R11 复用公开 Feature，不复制 PlaybackSession。
