# Qt6 + libmpv 播放器阶段实施任务书

> 版本定位：快速框架实施版  
> 范围：R2–R14  
> 原则：先把正确的模块框架和真实主链跑起来，再集中修复、补边界和做强验证。  
> 不包含：R0、R1；现有 R0/R1 状态不在本包中重新定义。

## 统一执行策略

本任务书不要求每个 Atomic Task 都先写成“工程合同”。普通任务只要明确目标、模块、主链、实现重点和基本验证即可直接开工。

整个项目按四个节奏推进：

1. **骨架优先**：先建立真正会被使用的目录、CMake、接口、对象所有权和最小实现，不创建大批空文件。
2. **主链优先**：优先让真实链路工作，例如 `libmpv → PlaybackSession → Render → ViewModel → QML`，先看到结果。
3. **边做边修**：编译错误、接口不顺、职责耦合、明显竞态、真实运行问题出现后立即在影响边界修复；普通边缘问题可记录到阶段修复清单，不要求每个小任务都阻断后续。
4. **集中硬化**：R12 专门负责压力、故障、性能、泄漏、长时间运行和最终架构审查；R13 再做真正发布门禁。

只有以下问题默认视为“必须先停下来解决”的硬阻断：

- 项目无法 configure/build；
- 主链完全不可运行；
- 明确的状态双重拥有、循环依赖或错误模块边界；
- crash、deadlock、use-after-free、线程越界等高风险生命周期问题；
- 数据损坏、不可逆迁移错误；
- Render/mpv 销毁顺序错误；
- 发布阶段安装包无法在干净机器启动。

普通 UI 细节、非主路径边缘场景、尚未覆盖的手工矩阵不需要阻止每个 Atomic Task 继续，但必须在阶段修复清单或 R12/R13 前关闭。

## 模块化总原则

- 一个模块只拥有一个清晰职责；新能力有独立状态、IO、生命周期、错误或测试边界时再拆文件/目录。
- 不为了“文件多”而拆；也不为了“改得少”把不同职责继续塞进同一个文件。
- QML 不直接调用 libmpv；PlaybackSession 是播放真值；Playlist 只拥有队列；DatabaseWorker 只拥有数据库连接；Renderer 只拥有 Render/OpenGL 资源。
- 所有源码/配置/行为变化继续同步记录根 `README.md`。
- R0-06 已按用户要求跳过，因此依赖合法可分发媒体 fixture 的验证，如果只有本地合法样本，必须写成“本地验证”，不能伪装成完整 fixture 体系已经闭环。

# Stage R6：播放器主界面与基础交互

## 1. 本阶段最终要得到什么

把前面的 Core、Render、Design System 组装成一个真正可以操作的播放器窗口。R6 完成时，用户已经可以把它当“基础桌面播放器”使用。

## 2. 本阶段怎么快速推进

优先顺序：PlayerScreen 骨架 → 视频 → 底部控制 → transport → timeline → volume → fullscreen。先让核心操作能用，再补自动隐藏、鼠标、Overlay、HUD 的体验问题。

## 3. 目标模块结构

```text
src/presentation/
├─ viewmodels/player/
└─ qml/screens/player/
   ├─ PlayerScreen.qml
   ├─ layout/
   ├─ overlays/
   ├─ drawers/
   └─ states/
src/presentation/qml/features/player/
├─ transport/
├─ timeline/
├─ volume/
└─ chrome/
```

## 4. 阶段主链

```text
PlaybackSnapshot
  ↓
Player / Feature ViewModels
  ↓
QML Controls
  ↓ intent
Action / PlaybackCommandBus
  ↓
PlaybackSession
```

## 5. 关键状态/资源归属

- 真实播放状态：PlaybackSnapshot。
- scrub 临时预览：Timeline interaction/session。
- hover/pressed/popup：QML/presentation。
- fullscreen 窗口状态：window controller。

拖动时 preview 接管 thumb；commit 只发一次 Absolute Seek；PendingCommit 在后台确认目标 position 前继续持有预览；媒体代际变化、non-seekable 或提交失败取消交互。

**基本验证**
拖动、取消、commit、pending 不抖回、duration 更新、generation 切换、non-seekable、unknown duration。

**完成判断**  
Timeline 不被后台旧 position 拉回；一轮 scrub 只提交一次 Seek；媒体切换后不保留旧预览。

**实际实施与验收**  
- 新增独立纯 C++ `TimelineScrubSession`，状态严格分为 `Idle / Scrubbing / PendingCommit`；只拥有 interaction generation 与 normalized preview，不拥有 Playback 真值。`begin/update/commit/cancel/cancelIfGenerationChanged/acknowledgePending` 均有独立边界，非有限值拒绝、有限值收敛到 0..1。
- 新增独立 `PlayerTimelineViewModel`，只消费 `PlaybackSnapshot.timeline` 与 Domain selector，发布 `canSeek/isScrubbing/seekPending/backendSeeking/displayedNormalized/durationSeconds/positionText/durationText`。`canSeek` 仅在 Ready + backend 明确 seekable + 有效 MediaGeneration + 正 duration 时成立；Unknown duration / non-seekable 均阻断交互。
- Scrubbing 期间后台 position 更新不会覆盖 preview；commit 时只发一次 `seekRequested(absoluteSeconds)` 并转入 PendingCommit。commit 冻结 **absolute target seconds**，同媒体 duration 后续刷新不会重算 Seek 目标；Pending 显示比例按冻结 absolute target / 最新 duration 反算。
- libmpv 现有 Seek encoder 的 Absolute 路径为 `absolute+exact`。PendingCommit 只在实际 position 到达冻结 target ±0.75s 后释放；generation 改变、seekability 消失或 CommandBus 立即拒绝提交均显式取消，因此 `seeking:true→false` 早于目标 position 到达也不会导致 thumb 回弹。
